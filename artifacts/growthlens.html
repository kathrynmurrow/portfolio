The problem

The performance development industry runs on snapshots.

01 The gap

Annual reviews reward recency, not reality

A manager's memory of who someone is gets compressed into whatever happened last. Three months of real progress disappear behind one rough week. The review captures a moment — and calls it a record.

02 The hidden cost

Coaching conversations evaporate

Every conversation a manager has disappears the moment it ends. There's no pattern, no follow-through record, no compounding. The next conversation starts from scratch — and so does the development.

03 The design premise

Development should accumulate — like a good manager's memory would

If a manager never forgot anything, never had recency bias, and could see patterns across every person they'd ever developed — what would their coaching look like? That's the system GrowthLens is designed to be.

04 Why AI

This isn't a documentation problem. It's an interpretation problem.

A form captures what happened. AI interprets what it means — whether confidence is the barrier or competence, whether this is a pattern or an outlier, what the right support is and whether it actually worked. That gap is where GrowthLens lives.

 Origin

This problem was lived before it was built.

Building coaching systems for 350+ school leaders and instructional coaches across one of Florida's largest school districts revealed the same failure pattern every time: coaching conversations happened and then vanished. No institutional record. No compounding. No way to know whether the support actually changed anything.

The feedback frameworks that emerged from that work — the Credible Feedback Process, the evidence-based observation system — were attempts to solve it structurally. GrowthLens is the AI-era answer to the same problem, rebuilt for enterprise scale.

The thesis hasn't changed: systems produce development, not isolated conversations. The tool has finally caught up to the idea.

What it does

Six capabilities. One connected record.

Continuous growth story

Every coaching conversation is logged and AI-interpreted into a living narrative — not a stack of disconnected notes. The story updates with each session.

Not documentation theater. The narrative is built to inform the next conversation, not satisfy HR.

Objectivity check

Before logging a coaching entry, AI surfaces whether the manager may be writing from frustration fatigue, recency bias, confirmation bias, or attribution error — protecting the person from being judged on bad data.

The tool is only trustworthy if it protects people while improving support quality.

Career ladder readiness

Missing evidence is labeled as "no evidence yet" — not "not capable." The tool tracks observed behavior against role expectations and surfaces what's needed to make a fair promotion recommendation.

Readiness is an evidence problem, not a judgment problem.

Fairness distribution view

Shows whether coaching, stretch opportunities, recognition, and accountability are being distributed consistently across the team — surfacing patterns a manager can't see in their own behavior.

Equity isn't a value statement. It's a measurable pattern.

Conversation rehearsal

Managers can practice difficult conversations before they happen — AI plays the employee in different states (defensive, disengaged, overconfident) and coaches the manager in real time.

Preparation produces better conversations than coaching frameworks alone.

System barrier escalation

When three or more people share the same development gap, AI surfaces a team-level or system-level pattern — so the manager knows when individual coaching is the wrong tool.

Individual coaching applied to a system problem produces frustration, not development.

Technical architecture

Built to be trustworthy, not just functional.

The stack reflects the same governing principle as the product: trustworthiness requires architecture decisions, not just good intentions.

Frontend Next.js + React + Tailwind

Component-driven UI with role-based views — manager coaching interface, employee growth plan, and team dashboard each surface only the data relevant to that role.

Auth + Data Supabase (Postgres + RLS + Auth)

Row-level security policies make per-user and per-org data isolation a database guarantee — not an application assumption. Private prep notes auto-delete on configurable schedules.

Same architecture pattern validated in Lead Sharper.

AI layer Anthropic Claude API

Prompt chains handle objectivity detection, growth story generation, support type recommendation, and system-pattern escalation. Human judgment owns every decision — AI surfaces evidence, not verdicts.

Integrations (roadmap) LMS + Operations data

Planned connectors for LMS completion data, operational KPIs, assessment results, and observation forms — so development records can be correlated with performance evidence.

Hosting Vercel

Serverless API proxy keeps AI keys off the client. Same pattern as Lead Sharper — proven to handle multi-user isolation without leaking credentials.

Governance Privacy by design

Private prep always stays private until the manager converts it. Formal action requires human review. AI never decides — it prepares the manager to decide better.
